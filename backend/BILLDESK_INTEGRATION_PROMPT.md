### API Authentication Headers (ALL REQUESTS)
- **BD-Traceid**: Unique identifier for each request (format: `{timestamp}-{random}` for idempotency)
- **BD-Timestamp**: Current timestamp in ISO 8601 format with timezone (YYYY-MM-DDThh:mm:ssTZD)
- **BD-Signature**: HMAC-SHA256 signature of request payload using Merchant Key
- **Content-Type**: `application/json`
- **Accept**: `application/jose`

### ENDPOINT 1: Create Order
**Path**: `POST /payments/ve1_2/orders/create`
**Purpose**: Create order and receive bdorderid and rdata from BillDesk

**Request Payload**:
```json
{
  "mercid": "KANAKV2",
  "orderid": "ORDER_ID_FROM_DB",
  "amount": "299.28",
  "order_date": "2026-05-27",
  "currency": "356",
  "itemcode": "PRODUCT_ITEMCODE",
  "ru": "https://yourdomain.com/payment-callback",
  "additional_info": {
    "email": "customer@example.com",
    "mobile": "+919876543210"
  }
}
```

**Response Structure**:
```json
{
  "bdorderid": "OAFC19XTFD8TSP",
  "rdata": "hex_string.encoded_suffix",
  "payment_link": "https://billdesk.com/payment?bdorderid=...",
  "success": true
}
```

**Key Points**:
- bdorderid is GENERATED BY BILLDESK - store this for subsequent API calls
- rdata is GENERATED BY BILLDESK - format is hex_string.encoded_suffix (NOT merchant-created)
- amount must be in two decimals (e.g., "299.28")
- currency "356" = INR
- orderid should be your internal order ID (alphanumeric, unique)
- Store bdorderid in Firestore orders collection for later reference

### ENDPOINT 2: Create Transaction
**Path**: `POST /payments/ve1_2/transactions/create`
**Purpose**: Initiate payment charge with card or payment method

**Request Payload**:
```json
{
  "mercid": "KANAKV2",
  "bdorderid": "OAFC19XTFD8TSP",
  "amount": "299.28",
  "itemcode": "PRODUCT_ITEMCODE",
  "auth_type": "3ds2",
  "device": {
    "init_channel": "web",
    "ip": "CLIENT_IP_ADDRESS",
    "user_agent": "USER_AGENT_STRING",
    "accept_header": "ACCEPT_HEADER",
    "browser_language": "en-US",
    "browser_javascript_enabled": true,
    "browser_tz": "Asia/Kolkata",
    "browser_color_depth": "32",
    "browser_java_enabled": false,
    "browser_screen_height": 1080,
    "browser_screen_width": 1920
  },
  "paymentdetail": {
    "paymentmethod": "card",
    "card": {
      "cardnumber": "4111111111111111",
      "expirydate": "12/25",
      "cvv": "123"
    }
  }
}
```

**Response Structure**:
```json
{
  "transactionid": "TXN123456789",
  "next_step": "3ds2_challenge",
  "auth_status": "0002",
  "redirect_url": "https://3ds-provider.com/challenge",
  "challenge_data": {
    "acsUrl": "...",
    "pareq": "..."
  }
}
```

**next_step Values**:
- `"redirect"`: Redirect to payment page
- `"capture_otp"`: Capture OTP from customer
- `"3ds2_challenge"`: 3D Secure 2.0 challenge required
- `"3ds2_frictionless"`: 3DS2 passed without challenge

**auth_status Values**:
- `"0300"`: Successful
- `"0002"`: Pending (awaiting additional authentication)
- `"0399"`: Failed

**Key Points**:
- Device information MUST be accurate (IP, User-Agent from request)
- auth_type "3ds2" is RECOMMENDED for security
- Only send card details for direct card payments (NEVER store/reuse)
- For network tokens, use paymentmethod "nwt" with card_token
- transactionid is generated by BillDesk - store immediately in Firestore

### ENDPOINT 3: Update Transaction
**Path**: `POST /payments/ve1_2/transactions/update`
**Purpose**: Authorize transaction after customer completes 3DS2/OTP authentication

**Request Payload (3DS2 flow)**:
```json
{
  "mercid": "KANAKV2",
  "transactionid": "TXN123456789",
  "bdorderid": "OAFC19XTFD8TSP",
  "response_parameters": {
    "cres": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

**Request Payload (OTP flow)**:
```json
{
  "mercid": "KANAKV2",
  "transactionid": "TXN123456789",
  "bdorderid": "OAFC19XTFD8TSP",
  "response_parameters": {
    "otp": "123456"
  }
}
```

**Response Structure**:
```json
{
  "transactionid": "TXN123456789",
  "auth_status": "0300",
  "authcode": "123456",
  "bank_ref_no": "BRN123456789",
  "rrn": "RRN123456",
  "mandate_setup_status": "SUCCESS"
}
```

**Key Points**:
- cres is JWT token received from ACS (3D Secure Server)
- otp is customer-entered OTP for OTP-based authentication
- auth_status "0300" confirms successful authorization
- Store authcode and bank_ref_no for reconciliation
- Save final transaction status to Firestore

## Backend Implementation Tasks

### 1. Create Firestore Collections/Documents
Create/update schema for:

**Collection: orders**
```
{
  orderid: string (primary key)
  userid: string (from Firebase Auth)
  bdorderid: string (from BillDesk)
  amount: string
  currency: string ("356")
  status: "created" | "pending" | "completed" | "failed"
  items: Array<{productid, quantity, price}>
  paymentmethod: "card" | "emi" | "nwt" | "otp"
  createdAt: timestamp
  updatedAt: timestamp
  expiresAt: timestamp (6 hours)
}
```

**Collection: transactions**
```
{
  transactionid: string (from BillDesk, primary key)
  orderid: string (reference to orders)
  bdorderid: string
  amount: string
  auth_status: "0300" | "0002" | "0399"
  next_step: string
  authcode: string (populated after Update Transaction)
  bank_ref_no: string
  rrn: string
  flow_type: "3ds2" | "otp" | "rupay"
  createdAt: timestamp
  updatedAt: timestamp
}
```

### 2. Create Backend Routes

**Route 1: POST /api/orders/create-order**
- Input: {userid, items[], paymentmethod, buyerEmail, buyerPhone}
- Calculate total amount
- Generate unique orderid
- Call BillDesk Create Order endpoint
- Store order and bdorderid in Firestore
- Return: {bdorderid, orderid, payment_link}

**Route 2: POST /api/orders/create-transaction**
- Input: {orderid, bdorderid, cardDetails OR tokenDetails, device_info}
- Extract device info from request (IP, User-Agent, etc.)
- Call BillDesk Create Transaction endpoint
- Store transactionid in Firestore
- Return: {transactionid, next_step, auth_status, redirect_url/challenge_data}

**Route 3: POST /api/orders/update-transaction**
- Input: {transactionid, bdorderid, response_parameters, flow_type}
- Validate transactionid and bdorderid exist in Firestore
- Call BillDesk Update Transaction endpoint
- Update transaction status in Firestore
- Return: {auth_status, authcode, bank_ref_no}

**Route 4: GET /api/orders/status/:orderid**
- Input: orderid (URL parameter)
- Query Firestore for order and associated transaction
- Return current status, transaction details, payment progress
- Used by frontend for polling

**Route 5: GET /api/orders/:orderid**
- Input: orderid (URL parameter)
- Return complete order details including all transactions
- Include timestamps and status history

### 3. Signature Generation Utility
Implement HMAC-SHA256 signature function:
```
function generateSignature(payload: object, merchantKey: string): string {
  const payloadString = JSON.stringify(payload);
  return crypto.createHmac('sha256', merchantKey).update(payloadString).digest('hex');
}
```

## Frontend Implementation Tasks

### 1. Payment Page Component

### 2. Payment Flow Implementation
```
Step 1: User clicks "Place Order"
  → POST /api/orders/create-order
  → Receive: {orderid, bdorderid, payment_link}
  
Step 2: Call Create Transaction
  → POST /api/orders/create-transaction
  → Receive: {transactionid, next_step, redirect_url}
  
Step 3: Based on next_step:
  
  IF "3ds2_challenge":
    → Redirect to ACS URL from challenge_data
    → Customer completes 3DS2 challenge
    → ACS redirects back with cres parameter
    
  IF "capture_otp":
    → Display OTP input form
    → Customer enters OTP
    
  IF "3ds2_frictionless":
    → Skip to Step 4 (no customer action needed)
    
  IF "redirect":
    → Redirect to payment page
    
Step 4: Call Update Transaction
  → POST /api/orders/update-transaction
  → Send: {transactionid, response_parameters}
  → Response will include auth_status
  
Step 5: Poll Order Status
  → GET /api/orders/status/:orderid (every 2 seconds)
  → Monitor for auth_status = "0300" (success)
  → Redirect to success page when complete
```

### 3. Polling Mechanism
Implement frontend polling:
- Start after Update Transaction call
- Interval: 2 seconds
- Max duration: 5 minutes
- Check: order.status === "completed" AND transaction.auth_status === "0300"
- Abort: auth_status === "0399" (failed)

### 4. Success/Failure Handling
- **Success**: Display order confirmation, transaction details, auth code
- **Failure**: Display error message with auth_status code
- Store transaction details in localStorage for reference
- Provide retry option for failed payments

## Security Considerations

1. **Never store card details**: Card data should NOT be saved anywhere
2. **Use network tokens** for recurring payments (tokenization)
3. **3DS2 mandatory**: Always use auth_type "3ds2" for card payments
4. **HTTPS only**: All payment pages must be HTTPS
5. **CORS protection**: Payment endpoints must have proper CORS configuration
6. **Rate limiting**: Implement rate limiting on payment endpoints
7. **Signature verification**: Always verify BD-Signature in responses
8. **Timeout protection**: Set appropriate timeouts (30 seconds max)
9. **Audit logging**: Log all payment-related API calls with timestamps
10. **Sensitive data**: Never log full card numbers, CVVs, or OTPs
