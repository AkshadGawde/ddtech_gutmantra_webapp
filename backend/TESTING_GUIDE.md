# BillDesk Payment Gateway - Complete Testing Guide

## Quick Start (5 Minutes)

### Test 1: Verify Server Is Running
```bash
# In your backend directory
npm start

# You should see:
# ✅ BillDesk routes registered
# ✅ Server listening on port 5000 (or your port)
```

### Test 2: Check Environment Variables
```bash
# Verify .env has correct values
cat .env | grep BILLDESK

# Should show:
# BILLDESK_MERCHANT_ID=KANAKV2
# BILLDESK_MERCHANT_KEY=to8pJnluXU43FPzhC2P2YLlbmylW4NEm
# BILLDESK_BASE_URL=https://uat1.billdesk.com/u2
```

### Test 3: Verify Routes Exist
```bash
# Check if endpoints are registered
curl http://localhost:5000/api/orders/status/TEST-123 \
  -H "Authorization: Bearer test-token"

# You should get a response (even if it's an error about missing order)
# If you get "404 - Route not found" then routes aren't registered
```

## Test Case 1: Create Order (10 minutes)

### What It Tests
- Backend can call BillDesk's Create Order API
- bdorderid is generated by BillDesk (not locally)
- Order is saved to Firestore

### Step 1: Get a Valid JWT Token
```bash
# If you have Firebase Auth set up:
# Go to your frontend and login with phone/OTP
# Copy the JWT token from localStorage

# Or create a test token programmatically:
# See your whatsappRoutes.ts for how tokens are generated
```

### Step 2: Run Create Order Request
```bash
curl -X POST http://localhost:5000/api/orders/create-order \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -d '{
    "userid": "user-123",
    "items": [
      {
        "productid": "ATTA001",
        "quantity": 1,
        "price": "299.28"
      }
    ],
    "paymentmethod": "card",
    "buyerEmail": "test@example.com",
    "buyerPhone": "+919876543210"
  }'
```

### Step 3: Expected Response
```json
{
  "success": true,
  "orderid": "ORD-1234567890",
  "bdorderid": "OAFC19XTFD8TSP",
  "amount": "299.28",
  "currency": "356",
  "payment_link": "https://uat1.billdesk.com/..."
}
```

### Step 4: Verify in Firestore
1. Open Firebase Console
2. Go to Firestore → `orders` collection
3. Find document with `orderid = "ORD-1234567890"`
4. Check fields:
   ```
   orderid: "ORD-1234567890"
   bdorderid: "OAFC19XTFD8TSP"  ← BillDesk generated this
   userid: "user-123"
   amount: "299.28"
   status: "created"
   createdAt: [timestamp]
   ```

### Step 5: Check Console Logs
Look for:
```
[BillDesk] Creating order...
[BillDesk] Order ID: ORD-1234567890
[BillDesk] Calling BillDesk API: POST /payments/ve1_2/orders/create
[BillDesk] ✅ Create Order successful
[BillDesk] BillDesk returned bdorderid: OAFC19XTFD8TSP
[BillDesk] Order saved to Firestore
```

✅ **Test Passed** if:
- Response has `bdorderid` (not null)
- Firestore shows order with status "created"
- Logs show successful API call

## Test Case 2: Create Transaction (15 minutes)

### What It Tests
- Backend can initiate payment charge
- Device info is captured correctly
- transactionid is generated by BillDesk

### Step 1: Get Order ID from Previous Test
Use the `orderid` and `bdorderid` from Test Case 1

### Step 2: Create Transaction Request
```bash
curl -X POST http://localhost:5000/api/orders/create-transaction \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -d '{
    "orderid": "ORD-1234567890",
    "bdorderid": "OAFC19XTFD8TSP",
    "amount": "299.28",
    "paymentmethod": "card",
    "cardNumber": "4111111111111111",
    "cardExpiry": "12/25",
    "cardCvv": "123",
    "deviceInfo": {
      "ip": "192.168.1.1",
      "userAgent": "Mozilla/5.0...",
      "acceptHeader": "text/html",
      "browserLanguage": "en-US"
    }
  }'
```

### Step 3: Expected Response
```json
{
  "success": true,
  "transactionid": "TXN123456789",
  "bdorderid": "OAFC19XTFD8TSP",
  "auth_status": "0002",
  "next_step": "3ds2_challenge",
  "redirect_url": "https://acsserver.com/challenge",
  "challenge_data": {
    "acsUrl": "https://acsserver.com/...",
    "pareq": "..."
  }
}
```

### Step 4: Verify in Firestore
1. Go to Firestore → `transactions` collection
2. Find document with `transactionid = "TXN123456789"`
3. Check fields:
   ```
   transactionid: "TXN123456789"
   orderid: "ORD-1234567890"
   bdorderid: "OAFC19XTFD8TSP"
   amount: "299.28"
   auth_status: "0002"  ← Pending
   next_step: "3ds2_challenge"
   createdAt: [timestamp]
   ```

### Step 5: Check Console Logs
Look for:
```
[BillDesk] Creating transaction...
[BillDesk] Calling BillDesk API: POST /payments/ve1_2/transactions/create
[BillDesk] ✅ Create Transaction successful
[BillDesk] transactionid: TXN123456789
[BillDesk] next_step: 3ds2_challenge
[BillDesk] Transaction saved to Firestore
```

✅ **Test Passed** if:
- Response has `transactionid` (not null)
- `next_step` is one of: "3ds2_challenge", "capture_otp", "3ds2_frictionless", "redirect"
- Firestore shows transaction with status "0002"

## Test Case 3: 3DS2 Challenge (Manual - 10 minutes)

### What It Tests
- Customer can complete 3DS2 authentication
- cres token is captured
- Update Transaction can process it

### Step 1: Redirect to ACS (Manual)
From Test Case 2, you got `redirect_url`. In a real browser:
1. Visit the `redirect_url`
2. You'll see 3DS2 challenge page
3. Complete the challenge (usually click "Accept" or similar)
4. ACS will redirect back with `cres` parameter in URL

### Step 2: Get cres Parameter
After 3DS2 completes, URL will be like:
```
https://yourdomain.com/payment-callback?cres=eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...&orderid=ORD-1234567890
```

Copy the `cres` value (it's a long JWT token)

### Step 3: Update Transaction with cres
```bash
curl -X POST http://localhost:5000/api/orders/update-transaction \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -d '{
    "transactionid": "TXN123456789",
    "bdorderid": "OAFC19XTFD8TSP",
    "orderid": "ORD-1234567890",
    "flowType": "3ds2",
    "cres": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..."
  }'
```

### Step 4: Expected Response
```json
{
  "success": true,
  "transactionid": "TXN123456789",
  "auth_status": "0300",
  "authcode": "123456",
  "bank_ref_no": "BRN123456789",
  "rrn": "RRN123456"
}
```

### Step 5: Verify in Firestore
1. Go to Firestore → `transactions` → "TXN123456789"
2. Check fields:
   ```
   auth_status: "0300"  ← Success!
   authcode: "123456"
   bank_ref_no: "BRN123456789"
   rrn: "RRN123456"
   updatedAt: [timestamp]
   ```

3. Go to Firestore → `orders` → "ORD-1234567890"
2. Check fields:
   ```
   status: "completed"  ← Updated!
   payment_status: "0300"
   updatedAt: [timestamp]
   ```

✅ **Test Passed** if:
- `auth_status` = "0300"
- Order status changed to "completed"
- authcode is populated

## Test Case 5: Webhook Reception (10 minutes)

### What It Tests
- Webhook endpoint receives BillDesk callbacks
- Webhook payload is logged
- Signature verification works

### Step 1: Check Webhook Debug Collection
```bash
# Go to Firestore Console
# Navigate to: webhooks_debug collection
# Look for documents created during Test Cases 1-4
```

### Step 2: Examine Webhook Payload
If you see documents in `webhooks_debug`:
```json
{
  "timestamp": "2026-05-27T10:30:45Z",
  "headers": {
    "x-billdesk-signature": "abc123def456...",
    "content-type": "application/json",
    "user-agent": "BillDesk-Webhook/1.0"
  },
  "body": {
    "transactionid": "TXN123456789",
    "orderid": "ORD-1234567890",
    "bdorderid": "OAFC19XTFD8TSP",
    "auth_status": "0300",
    "authcode": "123456",
    "bank_ref_no": "BRN123456789",
    "rrn": "RRN123456"
  }
}
```

### Step 3: Check Console Logs
Look for webhook processing logs:
```
[WEBHOOK] Received BillDesk webhook
[WEBHOOK] Signature Header: x-billdesk-signature
[WEBHOOK] Processing: txnid=TXN123456789, status=0300
[WEBHOOK] ✅ Signature verified: HMAC-SHA256 (hex)
[WEBHOOK] ✅ Updated order ORD-1234567890 to status: completed
```

✅ **Test Passed** if:
- `webhooks_debug` collection has data
- Signature verification shows "✅ Verified"
- Order status was updated by webhook

## Test Case 6: Error Handling (10 minutes)

```bash
curl -X POST http://localhost:5000/api/orders/create-order \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer INVALID_TOKEN" \
  -d '{...}'
```

```bash
"price": "0.01"

# Expected Error Response
{
  "success": false,
  "error": "Amount below minimum (₹1)",
```

```bash

"buyerEmail": null

  "success": false,
```

✅ **Test Passed** if:
- Errors are descriptive

## Debugging Tips

### If Create Order Fails
```bash
# Check logs for BillDesk API error
# Look for: "[BillDesk] API Error:" in console

# Verify Merchant Key matches:
echo $BILLDESK_MERCHANT_KEY
# Should show: to8pJnluXU43FPzhC2P2YLlbmylW4NEm

# Verify URL is correct:
echo $BILLDESK_BASE_URL
# Should show: https://uat1.billdesk.com/u2
```

### If Signature Verification Fails
```bash
# Check console for signature mismatch
# Look for: "[WEBHOOK] Signature verification failed"

# Verify merchant key in webhook code matches .env
# Add debug log: console.log('Received signature:', signature);
# Add debug log: console.log('Expected signature:', expectedSignature);
```

### If Polling Returns Empty
```bash
# Verify orderid exists in Firestore
# Check exact spelling/format
# Make sure you're using correct JWT token for that user
```

### If No Webhook Received
```bash
# Check Firestore: webhooks_debug collection
# If empty = BillDesk hasn't called your endpoint yet

# Verify callback URL is correct in BillDesk config
# Email BillDesk: "Please confirm webhook endpoint: https://api.gutmantra.in/api/billdesk/callback"

# As fallback, continue using polling (works but slower)
```

## Common Issues & Fixes

| Issue | Fix |
|-------|-----|
| 404 on payment endpoints | Routes not registered in Express app |
| bdorderid is null | Create Order API failed - check BillDesk error in logs |
| Signature verification fails | Check Merchant Key in .env is exact |
| transactionid is null | Create Transaction failed - check device info format |
| Webhook never received | Webhook URL might not be whitelisted - email BillDesk |
| 401 Authorization error | JWT token expired or invalid - get new token |
| timeout on API calls | Network issue or BillDesk server slow - retry |
